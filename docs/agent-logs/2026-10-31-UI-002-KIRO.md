## Decisions and alternatives
- Native WebGL was chosen over Three.js/GSAP because the fluid procedural scene does not require models or timeline orchestration. This adds no runtime dependency and keeps the interactive boundary small.
- The implementation recreates the cinematic visual language independently. It does not copy source code, images, 3D models, fonts or animation assets from the reference website.
- The first visual screenshot exposed below-fold sections at zero opacity before scrolling. The reveal baseline was changed to 78% opacity plus translation, so content remains readable even if observation does not fire; in-view content animates to full opacity.
- WebGL is `aria-hidden`; all meaningful text and links remain server-rendered HTML. Reduced-motion users receive one still shader frame, no moving ticker and no custom cursor.

## SEO / accessibility / performance changes
- Hero H1, CTA, service list, project names, awards and contact copy remain present in exported HTML before hydration.
- WebGL is decorative, CSS-backed and isolated in one client leaf; server/static components still own primary content.
- Canvas DPR is capped at 1.5. Rendering pauses when offscreen or hidden and stops on context loss/unmount.
- Reduced motion renders a still frame and disables reveal/ticker/cursor movement.
- Visible focus rings, skip link, semantic landmarks, labeled sections and native links/buttons remain intact.
- 4:3 procedural project fields reserve layout space and do not load external image assets.
